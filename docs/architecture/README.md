# 架构文档

本目录说明多组织 SaaS 平台的系统组成、授权模型、代码组织和请求运行过程。开发时必须遵守的规则由根目录及各应用、包的 `AGENTS.md` 维护；具体实施步骤由实施计划维护。

## 阅读顺序

| 顺序 | 文档                                 | 回答的问题                                     |
| ---- | ------------------------------------ | ---------------------------------------------- |
| 1    | [领域词汇](GLOSSARY.md)              | 用户、组织成员、角色、团队和归档分别表示什么？ |
| 2    | [应用架构](application.md)           | 系统有哪些应用和服务，它们如何协作与部署？     |
| 3    | [代码组织](code-organization.md)     | 代码如何划分，职责与依赖方向是什么？           |
| 4    | [请求与数据流](request-data-flow.md) | 浏览器、SSR 和接口如何读取、修改并同步数据？   |
| 5    | [权限架构](authorization.md)         | 谁可以对哪些数据执行什么操作？                 |

按问题选择专题即可，无需每次读取全部文档。涉及权限或组织生命周期时，优先阅读权限架构。

## 设计状态

- **当前实现**：已从仓库代码核对的能力。
- **已确认待实施**：产品规则和设计范围已批准，代码、模型或界面尚未完成。
- **条件性演进**：只有实际需求达到说明的条件时才考虑的方案。

图和文字必须区分上述状态。当前主业务由一个 TanStack Start 服务承载；权限方案已确认但尚未完整落地；独立 API 服务属于条件性演进。

## 文档职责

| 文档类型 | 内容                                     | 入口                                                 |
| -------- | ---------------------------------------- | ---------------------------------------------------- |
| 架构     | 系统职责、关系、约束、运行机制与设计取舍 | 本目录的专题文档                                     |
| 领域词汇 | 概念定义                                 | [GLOSSARY.md](GLOSSARY.md)                           |
| 开发约定 | 编码与验证时必须遵守的规则               | [根约定](../../AGENTS.md)、各应用和包的 `AGENTS.md`  |
| 决策记录 | 难以逆转或容易被误解的设计选择及原因     | [组织归档决策](../adr/0001-archive-organizations.md) |
| 实施计划 | 改动入口、阶段、模型处理、验收与待办     | [权限体系实施计划](../implementation/permissions.md) |

当前不单独维护 `docs/development/`。Web 的加载、缓存更新、表单、对话框和错误反馈规则放在 [Web 约定](../../apps/web/AGENTS.md)，共享组件、主题及样式规则放在 [UI 约定](../../packages/ui/AGENTS.md)。未来出现需要独立讲解的长篇教程时，再增加指南，并从对应约定链接过去。

## 维护方式

架构变化时更新对应专题和必要的决策记录；编码规则变化时更新对应 `AGENTS.md`。实施完成后更新当前实现状态，详细任务与检查结果继续记录在实施计划中。权限规则以权限架构为依据，其他专题只解释该规则在自身主题中的位置，避免复制整份权限矩阵。
