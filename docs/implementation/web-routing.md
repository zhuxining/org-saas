## 2. 范围与计划分工

本计划负责路由节点、URL 兼容、页面布局、登录导航、邀请流程及权限结果的页面接入。权限计划负责平台 Admin、动态角色策略、组织状态接口、归档／恢复及服务端访问限制。

| 内容           | 本计划职责                                          | 前置条件                               |
| -------------- | --------------------------------------------------- | -------------------------------------- |
| 公开与认证布局 | `_public`、`_auth`，公开首页不因登录改变            | 当前页面可迁移                         |
| 共享登录层     | `_authenticated`，提供用户上下文和登录返回地址      | 复用请求级 Session getter              |
| 个人中心       | `/dashboard` 迁移至 `/me`，资料、组织列表与创建入口 | 当前个人及组织能力                     |
| 组织布局       | 组织上下文外层、正常业务 `_active`、独立归档页      | 状态与权限结果由权限计划提供           |
| 平台布局       | `/admin` 平台守卫与导航                             | Admin 及最小平台权限已落实             |
| 角色页面       | 放置在正常组织分支，并接入相应操作检查              | 动态角色管理能力由权限计划提供         |
| 收藏与资源详情 | 保留目标位置和布局边界                              | 实际业务模型另行确定，不在本重构中实现 |
| API            | 保持直接 HTTP 接入，不纳入页面布局                  | 现有 handler 与独立服务端认证          |

不能为了完整画出目标树而提前开放没有服务端支持的管理页面。没有收藏业务时，不显示可误认为已经可用的收藏入口；不新增收藏表或资源接口。

| `/pricing`                               | `/pricing`              | `_public` 下对应页面                                    |

## 5. 布局与上下文约定

| 节点             | 检查                       | 提供给子层的内容                                                    |
| ---------------- | -------------------------- | ------------------------------------------------------------------- |
| `__root`         | 全站基础行为               | Router／Query 与基础 Provider                                       |
| `_authenticated` | 是否登录，处理有效返回地址 | 适合页面使用的用户上下文，不携带凭证或服务端实例                    |
| `me`             | 继承登录检查               | 个人导航，不加载组织内部业务                                        |
| `org/$orgSlug`   | 目标组织成员身份、可见状态 | orgId、slug、成员身份及受限状态，不依赖正常业务查询才能建立恢复入口 |
| `_active`        | 正常组织状态               | 正常组织导航；具体页面继续检查操作权限                              |
| `archived`       | owner 身份及适用状态       | 受限状态与恢复结果，不加载正常业务数据                              |
| `admin`          | 平台访问资格               | 平台导航；各页面检查对应平台操作                                    |
| `api`            | 自身 Session／权限策略     | HTTP handler 的请求 context，失败保持协议错误                       |

组织外层和 `_active` 分工避免归档恢复死锁；不能通过在父层提前读取完整组织、团队或统计来阻断恢复页面。按权限计划提供的最小组织上下文实现。

保留 `@org-saas/auth/session` 的请求级 getter；共享页面登录检查不替代业务 API 的独立认证和组织检查。布局、loader 和 SSR 中的浏览器可见数据排除 Cookie、token、数据库或认证服务实例。

## 6. 分阶段实施

### 阶段 0：迁移清单与生成行为核对

- 阅读 Web、Auth 及涉及的 API／UI 约定，重新核对生成工具版本与文件命名语义。
- 列出所有现有 URL、route ID、布局、搜索参数、跳转及回调；盘点硬编码字符串和类型断言，按目标类型化路由更新。
- 记录首页、登录、邀请、个人设置、创建组织、组织成员／团队及 API 的现有行为，作为迁移回归基线。
- 按第 4 节形成具体文件移动与旧地址重定向清单，保留现有私有组件。

完成条件：现有页面无遗漏，URL／ID 区分明确；只读核对不更改业务模型。

### 阶段 1：公开、认证与共享登录节点

- 迁移公共布局至 `_public`，保持所有公开地址，根首页无论是否登录均显示公开内容。
- 增加 `_auth` 页面布局，登录保持 `/login`；邀请流程保留独立分支，不继承登录入口的限制。
- 建立 `_authenticated/route.tsx`，用 `beforeLoad` 检查会话并提供用户上下文，布局只承载 Outlet，不增加业务导航。
- 调整登录流程及路由错误消费：未登录跳转登录，已登录无权限使用对应 fallback。
- 集中实现返回地址校验，处理查询输入；只允许有效的站内页面地址，拒绝外部 origin、协议相对地址、异常编码、凭证 URL 和导致登录循环的目标。浏览器和 SSR 使用相同语义，不能仅靠字符串以 `/` 开头判断。
- 登录成功使用合法目标地址，无合法目标则进入 `/me`。移动旧受保护页面时同步移除重复的页面登录检查，保留页面级授权。

完成条件：公开首页、未登录导航、合法／恶意返回地址及登录后无权限场景符合第 9 节。

### 阶段 2：个人空间与旧链接兼容

- 将 dashboard 布局和功能迁入 `/me`，统一界面称“个人中心”；Dashboard 仅用作空间内概览语义。
- 现有组织列表拆至 `/me/organizations`，创建至 `/me/organizations/new`，资料编辑迁到 `/me/settings/profile`；首页可复用组织入口，不重复维护查询。
- 更新公开用户菜单、个人导航、组织返回入口、组织切换器、登录成功和创建取消等所有引用。
- 为现有 dashboard 地址加入映射重定向；处理 SSR 直接请求和客户端导航，避免重定向链与重复布局。
- 收藏地址只作为后续业务位置，未实现时不开放空业务入口。个人记录按用户归属，组织入口仅展示用户获准看到的基础关联信息。

完成条件：已有个人功能完整可用，新旧链接均可到达正确页面；个人空间不加载未授权组织内部数据。

### 阶段 3：组织布局分层

- 移动组织父节点到 `_authenticated` 下，拆分身份／状态上下文与正常导航；正常页面迁到 `_active`，保持全部已有组织 URL。
- 使用权限计划提供的组织状态及成员检查，不借助写入 active organization 证明访问资格。
- 核对当前 `resolveOrgBySlug` 的 `setActiveOrganization` 副作用：预加载、SSR 与多标签页不能让目标 slug 和成员身份错配。按明确目标组织取身份，确需 active 状态的调用保持组织参数与当前请求一致。
- `_active` 先检查正常状态，子页面按操作权限加载数据；owner 的 archived 页面只加载受限状态及恢复接口。
- 保留成员和团队页面私有组件的局部性，更新引用与 route context；归档分支没有正常组织导航和业务预取。
- 归档／恢复后刷新相关缓存与路由状态，路由变化不能替代服务端的生命周期限制。

前置条件：权限计划阶段 2／3 提供必要状态、身份和业务接口。不能通过客户端硬编码“未归档”宣称该阶段完成。

完成条件：正常组织页面地址不变，非成员访问被拒绝，owner 可恢复归档组织，归档状态不泄漏普通业务数据，多标签页上下文一致。

### 阶段 4：邀请与平台管理接入

- 邀请页在未登录时显示最小信息并引导登录；不匹配账号明确提示并提供切换方式，登录后能回到原邀请流程。
- 接受邀请重新检查服务端结果，使用实际加入组织的 slug 导航，不再固定跳 dashboard；未知目标先重新取得授权后的组织信息，不凭外部输入构造目标权限。
- 正确处理过期、撤销、已处理、账号不匹配、归档及无效邀请，不让正常组织父层提前阻断邀请入口。
- 平台 Admin 与接口完成后再增加 admin 布局与页面，组织 admin 不能通过同名角色进入。角色页面由权限计划实现，在 `_active` 下接入。

完成条件：邀请与平台管理实际授权一致，API 端点不受页面导航结构干扰。

### 阶段 5：生成、验证与交付

- 通过现有工具重新生成路由树，检查 route ID、URL、父子布局与重复匹配；不手工修改 `routeTree.gen.ts`。
- 扫描旧 `/dashboard` 引用，允许只出现在明确重定向、回归验证和当前状态说明中；新页面不继续依赖旧地址。
- 运行根约定要求的 `vpr check`，再运行 `vp run --filter web build`。验证生成、TypeScript 路由类型、客户端／服务端边界与 SSR 构建。
- 根据第 9 节验证浏览器导航、直接请求、刷新、返回按钮和适用的预加载行为；为登录返回地址及归档恢复等具体缺陷风险增加必要行为测试。
- 更新架构当前实现状态与两份计划的完成结果，列出未开放页面和前置条件，不把尚未开发的收藏或业务资源标为完成。

完成条件：检查和回归通过，没有遗漏 URL；已交付阶段与仍依赖权限工作的阶段区分清楚。

## 7. 与权限实施计划的执行关系

路由阶段 0／1／2 可优先处理既有页面与 URL 迁移。阶段 1／2 应协同提交，确保 `/me` 及旧链接映射在登录目标切换时已可用。

组织归档分支依赖权限计划的服务端策略、模型和接口；Admin 与角色界面由权限计划负责业务能力，本计划负责放入正确布局与导航。两个计划共用一组页面，不各自重复开发。

本路由重构自身不需要改变持久化模型。若同时推进归档或 Admin，数据库生成、连接目标确认与应用变更仍按权限计划和 DB 约定执行，不归入“移动路由文件”自动处理。

## 8. 页面私有代码与加载方式

路由文件只承载参数、搜索验证、守卫、加载及页面接入。复杂页面的表格、表单和对话框就近放 `-components/`；只有实际跨页面复用才提取到 `src/components/`，多端业务保持共享 API。

查询复用既有 QueryClient 和 query options，loader 预取与组件消费保持一致。用户／组织切换清理或失效适用缓存，角色与组织状态变化更新 route context。SSR 凭证传递及缓存水合按实际集成验证，不能只通过客户端点击证明 SSR 可用。

编码细节由 Web 约定维护，本计划不复制表单、对话框及 UI 规则。

## 9. 验收场景

| 场景                                           | 期望结果                                         |
| ---------------------------------------------- | ------------------------------------------------ |
| 未登录或已登录访问 `/`                         | 都是公开首页，不自动跳个人中心                   |
| 直接打开 `/about`、`/pricing`、`/landing`      | 页面与公开布局保留                               |
| 未登录访问 `/me` 或组织／平台页面              | 跳登录并保留有效返回地址                         |
| 登录成功无有效返回地址                         | 进入 `/me`                                       |
| 登录成功返回无访问资格的组织／平台页面         | 显示拒绝访问，不循环登录                         |
| 外部 URL、协议相对地址、异常编码或循环登录目标 | 不产生外部或循环跳转，按默认目标处理             |
| 旧 dashboard 首页、profile、创建组织地址       | 分别到对应新页面，查询与 trailing slash 行为正确 |
| 新链接、菜单及类型化 route ID                  | 不依赖旧地址，生成树无重复匹配                   |
| 在个人、组织、平台之间导航                     | 同一账号，各自布局与上下文正确，不重复套业务导航 |
| 个人中心查看组织入口                           | 仅展示获准的基础关联信息，不混入组织内部业务     |
| 正常组织成员访问既有组织页面                   | 地址保持不变，页面与私有组件可用                 |
| 组织非成员访问或切换其他 slug                  | 页面与服务端均拒绝，不复用旧组织上下文           |
| 两个标签页／预加载进入不同组织                 | 请求数据及成员身份与明确目标组织一致             |
| 归档组织 owner 直接刷新 archived 页面          | 能查看受限状态及恢复，不被 `_active` 父层阻断    |
| 非 owner 访问归档恢复或归档组织普通业务        | 拒绝，无普通业务预取及受限数据泄漏               |
| owner 恢复后进入正常组织页面                   | 状态、缓存、布局与操作权限重新检查               |
| 未登录访问邀请链接                             | 能进入最小邀请流程并引导登录                     |
| 不匹配账号、过期／撤销／归档邀请               | 明确反馈，服务端不允许接受                       |
| 有效邀请接受成功                               | 进入实际目标组织，不固定跳个人中心               |
| 组织 admin 访问平台 admin 页面                 | 拒绝；平台权限独立判断                           |
